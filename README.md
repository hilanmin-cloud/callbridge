# CallBridge

방한 외국인 관광객을 위한 **식당 전화 예약 대행 서비스**의 프런트엔드입니다.

한국의 인기 식당 상당수는 온라인 예약 채널이 없고 전화로만 예약을 받습니다. 외국인 관광객은 언어 장벽 때문에 그 전화를 걸지 못하고, 한국 번호가 없어 식당의 확인 전화도 받을 수 없습니다. CallBridge는 이 연결을 대신합니다.

**배포 주소** → https://callbridge.vercel.app

---

## 화면 구성

| 파일 | 역할 |
|---|---|
| `index.html` | 랜딩 페이지 — 서비스 소개, 이용 방법, 요금, FAQ |
| `intake.html` | 요청 접수 폼 — 식당·희망 일시·허용 조건 입력 후 DB 저장 |
| `result.html` | 결과 페이지 — 요청 번호로 예약 결과와 식당 이용 안내 조회 |

운영자용 화면(통화 처리, 장소 DB 적재)은 고객 정보를 다루므로 이 저장소에 포함하지 않았습니다.

---

## 사용 기술

- **HTML5** — 시맨틱 요소, `<details>` 기반 FAQ, 스킵 링크, ARIA 속성
- **CSS** — Flexbox, 미디어 쿼리, CSS 변수, `prefers-color-scheme` 다크 모드, `clamp()` 반응형 타이포그래피
- **JavaScript (ES5)** — 의존성 없는 바닐라 구현, `fetch` API, `Intl.DateTimeFormat`
- **Supabase (PostgreSQL)** — REST API로 요청·고객·업체 데이터 처리
- **GitHub + Vercel** — 커밋 시 자동 배포

빌드 도구나 프레임워크 없이 **정적 파일만으로 동작**합니다.

## 구현에서 다룬 문제

### 다국어 — 번역이 아니라 현지화

방한 관광객 통계상 일본·중화권 비중이 60%를 넘어, 기본 언어를 일본어로 두고 5개 언어(일본어·중국어 번체·간체·영어·한국어)를 지원합니다.

- 각 언어권의 예약 문화에 맞는 표현 사용 — 좌석 형태를 일본어는 `カウンター・座敷・個室`, 중국어는 `吧台、和式、包廂`로 표기
- 날짜·시간은 `Intl.DateTimeFormat`으로 현지 형식을 따르되 **시간대는 한국 시간으로 고정** — 고객 기기가 자국 시간대일 때 예약 시각이 어긋나는 문제 방지
- 결과 페이지에서 안내문은 고객 언어, **식당에 보여줄 문장은 한국어**로 분리 — 읽는 주체가 다르기 때문

### 입력 구조 — 왕복을 없애는 설계

처음에는 희망 시간을 하나만 받았으나, 식당이 만석일 때 고객에게 다시 물어야 해 처리가 지연되는 구조였습니다. 1·2·3순위 일시와 허용 조건(좌석 분리 수용, 좌석 형태 무관 등)을 함께 받도록 바꾸어, 통화 중에 대안을 확정할 수 있게 했습니다.

대안 입력도 처음에는 체크박스였으나 사용자가 원하는 구체적 시간을 고를 수 없어 날짜·시각 선택 방식으로 재설계했습니다.

### 반응형 — 폴더블 대응

폴더블 기기의 접힌 상태(약 380px 폭)에서 날짜·시간 입력 요소가 컨테이너를 벗어나는 문제를 확인하고, `flex-wrap`과 미디어 쿼리로 세로 배치되도록 수정했습니다.

### 접근성

- 체크박스 라벨 영역 전체를 클릭 가능하도록 `<label for>` 연결
- 터치 대상 최소 높이 44px 확보
- 스킵 링크, `aria-labelledby`, `aria-pressed` 적용
- `input type`을 용도에 맞게 지정해 모바일에서 적절한 키보드 노출

### SEO

- 페이지별 title·description, canonical, Open Graph
- `hreflang` 5개 언어 + `x-default`
- JSON-LD 구조화 데이터 — `Service`, `FAQPage`, `HowTo`
- `robots.txt`와 `sitemap.xml`, 결과 페이지는 `noindex`로 색인 제외

## 데이터 구조

```
customers ─┐
           ├─ requests ─┬─ request_slots      (순위별 희망 일시)
venues ────┘            ├─ request_conditions (통화 중 확정 가능 범위)
                        ├─ calls              (통화 기록)
                        └─ results            (결과 보고)
```

업체 데이터는 공공데이터포털의 지방행정 인허가 정보를 가공해 적재하고, 통화 결과로 전화번호 검증 이력을 축적하는 구조입니다.
